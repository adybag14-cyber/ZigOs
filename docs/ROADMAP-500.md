# ZigOs 500-goal operating-system roadmap

This roadmap converts the broad runtime, process, filesystem, userland, networking, build, testing, hardware and security gaps into 500 individually trackable engineering goals. A checked item means the repository contains the claimed implementation and at least one executable test or release contract; it does not imply production readiness. Each completed goal should also state whether its evidence is source-only, isolated-unit, QEMU integration or required hosted CI. Bounded Capstone fixtures do not automatically satisfy a general-runtime goal.

ABI 1.15 then completes **G237** with path syscall 122 `stattimes` and a fixed 32-byte four-u64 `FileTimes` result while preserving the legacy 32-byte `stat` layout. Every bounded VFS inode stores creation, modification, change and access ticks. Persistent journal format v2 embeds those four values in each existing record header without changing namespace record counts; v1 journal generations remain readable by synthesizing all four fields from the restore tick. Hard-link restoration reapplies the shared inode metadata after alias reconstruction, full `fsync` records the current four-field metadata, and `fdatasync` advances the data modification tick while retaining previously committed creation/change/access metadata and mode. An isolated VFS test proves independent storage and a persistence test restores exact directory, file/hard-link and symlink values. **G238** completes the timestamp policy without changing ABI 1.15: the persistent runtime samples its boot-local LAPIC service counter at 100 Hz, giving nominal 10 ms precision; the counter resets to zero each boot and multiple operations within one scheduler tick may tie, so stored values are ordering metadata rather than wall-clock or cross-reboot-monotonic time. Successful create/mkdir/symlink initialize all four fields and update the containing directory modification/change ticks; nonzero writes, truncation and allocation changes update file modification/change; nonzero reads update access; chmod updates change; link updates the target change tick plus the destination-directory modification/change ticks; unlink updates a surviving inode change tick plus the parent directory; rmdir updates its parent; rename updates the moved inode change tick and every affected parent, plus a surviving replaced inode; nonzero readlink/getdents update symlink/directory access. Stat/stattimes and synchronization calls are timestamp-neutral, as are failed operations, zero-byte non-truncating reads/writes, EOF getdents, read-only mapped-file access and kernel-internal namespace/snapshot scans. Persistence reapplies stored timestamps only after namespace and hard-link reconstruction so restore-side parent mutations cannot corrupt journal metadata. One exact host policy test and the booted Zig SDK fixture prove data, metadata, namespace and access ordering; persisted values may numerically decrease after reboot when a fresh boot-local tick replaces an older stored value. **G239** is completed by ABI 1.16 syscall 123 `statowner`: every bounded VFS inode stores a 32-bit UID/GID pair; descriptor-created files, mkdir and symlink inherit the creating process credentials; hard links preserve the shared inode owner; and the fixed public result is an independent 8-byte `FileOwner` structure so legacy `stat` remains unchanged. Persistent journal v3 extends each record header to 48 bytes with UID/GID, reads v1/v2 records as root-owned `0:0`, and reapplies ownership after hard-link reconstruction. Existing host tests prove non-root `1000:1000` creation, exact nonzero directory/file-hardlink/symlink/sparse-file ownership after reboot and v1/v2-to-v3 migration; Zig and C CPL3 fixtures exercise `statowner`. G240 completes owner/group/other enforcement on top of the same ABI 1.16 metadata. UID 0 is the bounded administrative bypass; every non-root check selects exactly one class in owner → matching primary GID → other order. Directory traversal requires execute; create/link/unlink/rmdir/rename require write+execute on the relevant parent namespace; requested read/write access is validated when a file or directory description is opened; process launch requires execute without requiring read; and chmod is owner-or-root. Open descriptions intentionally retain access after later chmod rather than rechecking pathname mode bits on every I/O. The expanded descriptor/VFS host proof covers owner, group, other, class precedence, primary-group directory mutation, execute-only access, root bypass, chmod ownership and retained-open semantics. Supplementary groups, `chown`, umask, setuid/setgid and sticky-directory rules are separate later goals. **G241** completes process umask through ABI 1.17 syscall 124. Every process stores a bounded nine-bit mask, children inherit the parent value, and `umask` returns the previous mask while rejecting bits outside `0777` without changing state. Descriptor `open`/`openat` creation and `mkdir` apply the mask to rwx bits exactly once; chmod, existing inodes, hard links and fixed-mode symlinks are unaffected. Userspace child spawn now preserves the parent UID/GID rather than resetting credentials. Host process/descriptor tests and independent Zig/C CPL3 fixtures prove inheritance, file `0666 -> 0640`, directory `0777 -> 0750`, invalid-mask failure atomicity and restoration. G242 then extends the same ABI 1.17 mode field with inert setuid/setgid metadata. Set-ID bits survive creation, chmod, stat, hard-link identity and journal v3 restore; full fsync commits current mode while fdatasync retains committed mode, and spawn never consumes those bits for credentials. G243 expands the validated mode mask to `07777` and makes sticky `01000` authoritative for deletion. Parent write+execute remains required; unlink and empty-directory rmdir, rename source movement and rename destination replacement each additionally require UID 0, the sticky directory owner or the victim owner. Exact rename-to-self remains a no-op. The expanded host credential proof covers unrelated-user denial plus victim-owner, directory-owner and root success, including replacement rename; persistence restores a `03755` directory and the Zig/C CPL3 fixtures round-trip sticky metadata. Supplementary groups, `chown`, set-ID execution and setgid-directory GID inheritance remain open. ABI 1.18 then completes **G244** with syscall 125 `flock`: shared/exclusive/unlock plus optional nonblocking acquisition on regular VFS files. Lock ownership is the shared open description, so `dup` and cloned-process aliases share state and final-reference close releases it; independently opened hard-link aliases conflict by inode generation. Shared locks coexist, exclusive locks conflict, nonblocking conflict returns `EWOULDBLOCK`, and blocking acquisition sleeps on a process-table file-lock wait key until unlock/final close wakes retry. The host descriptor tests prove hard-link identity, advisory-only conflicting I/O, scheduler block/wakeup, conversion behavior, dup/fork lifetime and final-close release; Zig/C CPL3 fixtures independently exercise the generated ABI. Locks are transient and absent from journal state. ABI 1.19 completes **G245** with syscall 126 `lockrange`: positive half-open byte ranges are bounded to the 32 KiB file address space and each shared open description carries at most eight normalized non-overlapping segments. Independently opened aliases conflict by inode generation; shared overlap is compatible, exclusive overlap conflicts, adjacent equal modes merge, replacement preserves unaffected fragments and partial unlock may split. Nonblocking conflicts are failure-atomic, while blocking conversion releases only the requested overlapping owner range before sleeping on the existing file-lock wait key. The host proof covers boundary overlap, non-overlap, split/merge, advisory writes, scheduler wakeup, dup/fork/final-close lifetime and deliberate independence from whole-file `flock`; Zig/C CPL3 fixtures independently exercise the generated ABI. Range locks are transient and never journaled. ABI 1.20 then completes **G246** with syscall 127 `watchdir` and a fixed 64-byte Zig/C `DirectoryEvent`. Each watch is created from an existing directory descriptor and starts at the current VFS namespace-mutation sequence. A bounded global 64-record journal reports create/remove and ordered rename-from/rename-to events; successful open-create, mkdir, hard-link and symlink publication enter the same stream. Separate watches keep independent cursors, dup/fork aliases share one open-description cursor, caught-up reads return `EWOULDBLOCK`, `poll` exposes readiness, and lag beyond retention yields an explicit overflow record. Generation checks prevent stale directory reuse, and watch/event state is transient across close/process teardown/reboot and absent from the persistent A/B journal. ABI 1.10 completes **G196** with generated 16-byte `IoVector` layouts, syscalls 116/117 `readv`/`writev`, an eight-vector and 1,024-byte total bound, complete descriptor/data-range prevalidation, one gathered descriptor write or one descriptor read followed by scatter, and Zig/C failure-atomic boot proofs. ABI 1.11 completes **G198** with syscall 118 `fdatasync`: it refreshes the target record data, logical size and sparse allocation map while retaining mode from the prior committed record. A four-boot A/B proof kills QEMU after both the full-file and data-only generations, verifies hard/symbolic aliases, excludes unrelated dirty sparse state and confirms dirty chmod metadata does not survive fdatasync. The all-writable-mount synchronization slice completes **G199** by prevalidating the active mount table before I/O, visiting every writable mount in ID order, treating RAM filesystems as immediately synchronized, committing the configured `zigos_persist` mount exactly once, skipping read-only mounts and rejecting unsupported or duplicate durable backends without advancing the journal. Diskless RAM-root userspace now receives successful global `sync` rather than a persistence-capability error. The bounded file-page-cache slice completes **G200** with a separate sixteen-entry file-data LRU keyed by node index, node generation and logical 4 KiB page. Ordinary file reads hold the inode data lock and load or hit cached pages; absent sparse blocks cache as zero pages. Writes, truncation, hole punching, sparse restoration and final inode reclamation update the authoritative shared block pool and invalidate every cached page for that inode. Runtime gates require bounded nonzero occupancy, real hits and misses, insertions and fully drained cache-lock tickets in persistent, live-network, normal and diskless profiles. A QEMU regression exposed that iterating the 64 KiB cache array by value could overflow/corrupt kernel execution state; every scan is now indexed or reference-based and the source contract forbids by-value cache-array iteration. The dirty-page slice completes **G201** with an eviction-independent one-byte logical-page bitmap per inode; resident entries mirror the authoritative bit for their generation-keyed page. Writes and allocation/size changes mark exact affected pages, cache eviction cannot lose the ledger, successful global sync clears all writable mounts only after its validated plan and journal commit, RAM-backed regular-file fsync/fdatasync clears only its target immediately, and persistent fsync/fdatasync clears only the target after journal commit. Rejected mount plans retain dirty bits for retry. A real persistent device-write or flush failure is handled separately by G229 through fail-stop read-only remount and dirty-ledger discard. Restored journal data and pre-seeded namespaces adopted as read-only become clean baselines, while inode destruction discards obsolete bits. All runtime profiles require zero resident dirty entries, zero dirty pages/nodes, nonzero real marks and synchronization clears at shutdown. Writes remain synchronous/write-through. The asynchronous-writeback slice completes **G202** with a single active generation-tagged request: scheduling records the inode, generation, dirty-page mask and persistent classification without clearing data; one subsequent timer-driven runtime service pass consumes at most one request. RAM-backed files complete in that worker by clearing the target ledger, while stable persistent files reuse data-only `fdatasync` journal semantics. A second request while active is rejected as busy; inode deletion/reuse is stale; new persistent paths are unsupported until global sync; busy, unsupported and stale outcomes retain the ledger for explicit retry; a persistent journal I/O failure is handled by G229 through fail-stop read-only remount. Request, completion, pass, outcome and queued/completed-page counters obey a conserved idle-or-complete shutdown invariant. The required diagnostic QEMU sessions schedule the six-page `/bin/sdk.elf`, return to the shell before completion, allow a later service pass and then observe exact `1/1/1` request/completion/pass and `6/6` page accounting. The four-boot persistence harness permits a healthy idle worker and retains the existing A/B recovery sequence. The pressure-reclaim slice completes **G203** by moving cache page bytes out of the VFS object into independently allocated post-bootstrap PMM pages, checking a bounded low watermark on each runtime service pass and evicting only clean LRU entries until the target occupancy is met. Dirty resident entries and eviction-independent dirty ledgers are retained. The current required 54/56-command QEMU sessions force pressure through the same path, prove seven pages returned to the PMM while dirty pages remain and require all remaining cache pages released before final PMM accounting. The policy is a bounded low-watermark mechanism rather than global OOM selection. The page-writer slice completes **G204** with eight ticket locks per inode, one for each bounded logical 4 KiB page. Ordinary and append writes acquire affected pages, replacement writes conservatively acquire all pages, and truncate, preallocation, hole punching and sparse restore acquire in ascending order and release in reverse. Four host threads perform 128 writes into disjoint regions of one cached page with exact page/inode ticket counts and intact final data; both diagnostic QEMU profiles report 186 page-write tickets and zero outstanding after removing the three RAM-backed boot-file copies. The existing inode data lock remains the outer boundary, so parallel writes to different pages are not claimed. ABI 1.12 then completes **G119 and G205** with generation-safe read-only file-backed `MAP_SHARED`: readable regular-file descriptors resolve to inode generation and size, each mapped logical page borrows and pins the PMM-backed VFS cache page, pressure and normal LRU eviction skip pins, ordinary writes refresh the mapped physical page, and close/unlink retain the inode until final unmap. A real CPL3 Zig fixture opens the descriptor before `chmod 000`, maps a 13-byte partial final page, and proves initial mapped reads, retained-descriptor write coherence, file-read equality and post-close/post-unlink lifetime; offline/live shutdown require exact mapped refs/pin/unpin/refresh/fail `0/1/1/1/0`, zero failures and zero remaining file mappings. Writable file mappings, file-backed `MAP_PRIVATE`, mapped writes, `msync` and mapped-write persistence remain open. The retained-boot-filesystem slice then completes **G206 and G207**: the kernel preserves the verified EFI GPT partition and passes its LBA extent to a dedicated read-only FAT16 backend; bounded 8.3 directory metadata is imported into VFS while file bytes remain on NVMe. Chain loops are rejected with visited bitmaps, FAT sectors are cached, sequential reads retain a cluster cursor, logical backed bytes are excluded from RAM accounting and a ticket lock protects shared sector buffers. A standalone image test traverses nested directories and streams a 33 KiB file; required 54/56-command QEMU sessions list `/boot` and `/boot/EFI/BOOT`, read deterministic root/nested files, stat the multi-mebibyte EFI, and require three files, two directories, zero failures and drained locks. Persistent normal proves metadata-only mount validation; diskless normal proves an explicitly absent backend with the embedded fallback. The FAT-integrity slice additionally completes **G221 and G222** by traversing every imported chain through EOC, separating same-chain loop detection from global cross-chain ownership, and rejecting invalid current or next-cluster values with explicit range accounting. Healthy diagnostic QEMU claims 10,912 clusters and normal QEMU claims 10,812 with zero loop/cross/range events. The quarantine slice completes **G223** by staging all FAT namespace metadata before VFS publication and, for classified loop/cross-link/range/structure failures, erasing staging, retaining one reason/event and mounting the embedded read-only fallback. A required QEMU image cross-links only non-boot `BOOT.CFG`, proves corrupted names are absent, and completes normal shutdown with exact classified telemetry and balanced resources. This does not repair media or guarantee rollback for a later VFS resource failure during publication. The block-I/O propagation slice completes **G228**: runtime FAT data-read failure maps to VFS `InputOutput` and userspace `EIO`, leaves the destination buffer and descriptor offset unchanged, and permits retry. CPL3 `read` and `readv` perform descriptor I/O under the kernel CR3 and restore the exact process CR3 before userspace copies. Every phase-valid NVMe completion advances and acknowledges the CQ before error classification.
