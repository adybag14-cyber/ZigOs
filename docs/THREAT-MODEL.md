# ZigOs x86-64 threat model

## Scope

This document describes the security boundary of the current bounded x86-64 ZigOs runtime. It is a development threat model, not a claim that ZigOs is secure against hostile workloads.

The model covers the post-UEFI kernel, retained CPL3 processes, the bounded RAM VFS, the retained read-only `/boot` FAT volume, the `/persist` A/B journal, COM1/TTY input, the retained e1000e and NVMe paths, and the generated ABI 1.20 SDK interfaces. The legacy i686 environment is outside this document.

## Assets to protect

- Kernel code, data, stacks, page tables, descriptor tables and interrupt state.
- Isolation between retained CPL3 address spaces.
- Physical-page ownership and allocator metadata.
- Process, descriptor, socket and VFS namespace integrity.
- Persistent journal generation, payload and commit ordering.
- Device MMIO, DMA buffers and retained controller state.
- Availability of the scheduler, TTY, VFS, storage and network service loops.

## Trust assumptions

The current release trusts:

- the UEFI firmware, ACPI tables accepted by the existing validators and the booted EFI image;
- the kernel image and all boot-embedded userspace ELF assets;
- QEMU hardware models used by the required integration tests;
- a single administrative user model with UID/GID-equivalent root authority;
- physical memory not being modified by an external DMA-capable attacker;
- a uniprocessor permanent runtime, because scheduler and allocator mutation are not SMP-safe.

The current release does not establish a package-signing or executable-trust chain for arbitrary files copied into `/persist`.

## Attacker model

A relevant attacker may control an unprivileged CPL3 program and may:

- issue any published syscall with malformed, non-canonical, overflowing, aliased or unmapped pointers;
- consume process, descriptor, socket, mapping and page quotas;
- fault deliberately, loop indefinitely, block on I/O or race logical lifecycle transitions on the BSP;
- create malformed paths, rename trees, mutate writable VFS files and provide malformed UDP/DNS data;
- provide malformed FAT boot-volume metadata or cluster chains and corrupted or stale `/persist` journal sectors between boots;
- send arbitrary serial input to the foreground TTY session.

The model does not currently defend against malicious kernel code, compromised firmware, physical attacks, hostile DMA, speculative-execution attacks, or concurrent malicious execution on several CPUs.

## Existing mitigations

### Memory and execution

- CPL3 processes use private CR3 address spaces and user/supervisor page separation.
- NX and W^X are enforced for supported mappings.
- User pointers and full-width descriptor/flag values are validated before narrowing or copy-in/copy-out.
- Process faults are contained and terminal contexts are reclaimed.
- Stack regions include unmapped guards, although stacks remain fixed-size.
- Physical pages have ownership, generation and reference accounting, final-release poisoning and double/wrong-owner rejection.
- Read-only shared file mappings borrow generation-tagged PMM-backed VFS cache pages; access is fixed by the validated open description rather than re-evaluated pathname mode, mapping pins block eviction and inode reclamation, ordinary writes refresh the mapped page, and unmap/process teardown must release the pin. Writable file mappings are rejected.

### Resource control

- Process, child, descriptor, socket, mapping and page counts are bounded.
- Descriptor and process handles are generation-tagged.
- Directory notification storage is globally bounded to 64 VFS mutation records; each watch consumes only an existing descriptor/open-description slot and reports overflow when retention is exceeded.
- Shutdown validation requires zero retained userspace contexts, descriptors and owned pages.
- The diagnostic shutdown path performs a bounded quiescence and terminal-child reap rather than accepting delayed lifecycle leaks.
- G258 makes shell command status explicit control data. Foreground children contribute their exact 32-bit kernel wait status; shell-generated failures use bounded 0/1/2/127 values, and the `status` builtin exposes only the immediately previous parsed command status. This status is not an authorization signal and is not persisted. G259 uses it as the bounded control input for `&&`/`||`, and G260 carries the resulting status across bounded semicolon-list boundaries.
- G259 treats conditional parsing as a side-effect boundary. The shell validates the complete four-command-maximum `&&`/`||` list before running its first segment, so malformed trailing/consecutive operators or overflow cannot partially execute a valid prefix. Operators are recognized without requiring spaces and have intentionally simple equal-precedence, left-to-right semantics. A skipped branch retains the current status and cannot mutate state because it never reaches `execute`; syntax failures return status 2. This is not quoting, expansion, pipelines or job control, and conditional status must not be treated as an authorization decision. G260 now adds semicolon sequencing as a separate outer parser layer.
- G260 extends the same side-effect boundary to sequential lists. The complete line is split and validated into at most four semicolon-separated conditional lists before `executeCommandLine` runs the first one. Empty middle lists and overflow are therefore rejected before a valid prefix can mutate state. A trailing delimiter is explicitly allowed, list status is carried only as shell control data, and `;` always advances to the next list regardless of success or failure. The fixed parser bounds limit memory/CPU exposure; this remains neither quoting-aware syntax nor a security boundary, and no list status confers authority.
- G261 treats pipeline process-group membership as spawn-time process metadata rather than a post-spawn race. ABI 1.21 exposes only two restricted `spawnv` modes: create a child-led pipeline group or join an existing same-parent/same-session sibling leader; arbitrary userspace process-group reassignment remains outside this interface and G141 stays open. The kernel validates the requested leader before installing a runnable child context, and missing/foreign groups fail closed. Shell pipeline syntax is fully bounded to four stages and multi-stage builtins are rejected before the first child starts. This PGID is coordination state, not an authorization credential. G261 deliberately left every stage on inherited shell descriptors and left the shell's TTY group foreground. G262 now establishes bounded adjacent-stage pipe data flow and child descriptor isolation; G263 now establishes controller-only foreground-group transfer and direct-child group waiting; background job state, stop/continue policy and richer terminal job control remain later goals.
- G262 treats pipeline descriptor inheritance as a spawn-time capability reduction. ABI 1.22 accepts pipe stdio remapping only for G261 grouped spawns; sources must be inherited fd>=3 pipe endpoints with the correct direction, and the child closes all inherited nonstandard descriptors before a runnable context is installed. The shell closes its copies stage-by-stage and on every partial failure, so unrelated inherited descriptors cannot keep pipe reader/writer reference counts alive and suppress EOF/broken-pipe behavior. The packed descriptor argument is bounded to two u16 values with an explicit inherit sentinel and rejects nonzero high bits. This does not authorize arbitrary files or descriptor actions, does not isolate the shell from all descriptor side channels, and does not transfer TTY foreground ownership; G263 remains the required terminal/job-control boundary.
- G263 treats foreground terminal ownership as a controller capability rather than a descriptor capability. Normal boot transfers the TTY internal controller from PID 1 to PID 2; a process merely inheriting fd 0/1/2 cannot invoke foreground-PGID changes. The controller can choose only its own PGID or an unreaped direct-child group leader in the same session, and group `wait` matches only direct children with the requested PGID. A terminal-but-unreaped leader remains an eligible handoff target because its PID/PGID, parent and session metadata are still authoritative; this closes the scheduler race where a short-lived group leader exits between grouped spawn and foreground transfer without allowing foreign, reaped or cross-session groups. Blocked group waits carry an explicit group-target bit so an unrelated child termination cannot spuriously wake the shell. The normal proof additionally requires the shell prompt to remain absent until an interactive foreground pipeline consumes terminal input, then verifies restoration to PGID 2. This does not create POSIX sessions, controlling-terminal acquisition/revocation, arbitrary `tcsetpgrp`, stopped-job accounting or orphan-group semantics; G264 provides bounded completion notifications and G265 adds running-job `fg`/`bg`, while broader stop/session controls remain G141-G146; G266 now handles terminal interrupt/suspend key generation only.

- G264 keeps background execution as bounded shell bookkeeping rather than adding ambient kernel authority. Only a trailing, fully prevalidated external pipeline may enter one of four fixed job slots; background builtins are rejected before side effects, and the shell never grants a background PGID terminal foreground ownership. Existing ABI 1.23 process-group `WNOHANG` waits reap only the shell's direct children, so completion polling cannot consume unrelated processes. The shell preserves final-stage status only for the notification, does not overwrite the foreground command-status channel, and returns to blocking terminal reads whenever the job table is empty. This is completion notification rather than stopped-job control; G265 now operates `fg`/`bg` on retained running jobs, while SIGCONT-style policy, stopped-job notification/resume, orphan groups and general session management remain open; G266 now supplies bounded terminal suspend-key generation.

- G265 does not add a signal capability or general job-control authority. `fg` and `bg` may reference only one of the four job slots already retained by the shell from its own direct-child launches. `fg` reuses the controller-restricted G263 foreground-PGID ioctl and direct-child group wait, so it cannot adopt an arbitrary process group; `bg` on a retained running job is an idempotent userspace bookkeeping operation and never changes TTY ownership. Invalid or empty slots fail without mutation. Because no userspace stop/continue primitive is exposed, G265 deliberately cannot resume stopped jobs and does not close G144-G146; G266 now handles only the terminal control-key generation side.

- G266 recognizes Ctrl-Z only inside the trusted TTY line discipline and directs signal 19 exclusively to the TTY's already-authorized foreground PGID; arbitrary userspace processes still gain no group-signal capability. Ctrl-Z clears uncommitted canonical edit bytes, has its own bounded telemetry counter and echo action, and uses the existing process-table permission checks/state transition. Ctrl-C remains separately accounted and retains exit-130 default handling. The host proof explicitly resumes the stopped test group only through the pre-existing internal signal-18 path. No userspace SIGCONT, stopped-child wait result or parent stop/continue notification is exposed, preventing G266 from silently widening authority beyond terminal key generation; those semantics remain G144-G146.

- G267 treats shell assignment as bounded exported state rather than arbitrary environment mutation. Only a single-word `NAME=VALUE` command with identifier grammar `[A-Za-z_][A-Za-z0-9_]*` is recognized; entries are capped by the existing 63-byte environment-string limit and stored in four fixed shell slots. Reassignment updates the matching slot in place. Child environment construction starts from the validated inherited environment, replaces matching keys, appends new keys only while the existing eight-entry ABI has capacity, and fails closed rather than truncating. Assignment stages are rejected before pipeline/background launch, so `PATH=/blocked &` cannot mutate shell state after syntax failure. There is no `export`, `unset`, temporary command-prefix assignment, value expansion or startup-file evaluation; all retained assignments are deliberately exported to later children.

- G268 bounds command substitution as explicit data capture rather than general recursive shell evaluation. Only a whole argument token `$(PROGRAM)` is recognized, the inner program executes as the shell's ordinary direct child with no extra authority, and its stdout is isolated in a kernel pipe capped at 31 bytes. An additional-byte probe rejects overflow instead of truncating; closing the read end and reaping the child prevents an overflowing writer from pinning shell resources. Empty-after-trim output, embedded NUL, nonzero child exit and lookup/I/O failures all abort the outer command before execution. Substitution is rejected during background and multi-stage pipeline prevalidation so no hidden inner child can run after partial outer launch. There is no nesting, inner argument/operator parsing, word splitting, command-position substitution or assignment-value expansion.

- G269 treats wildcard expansion as bounded namespace enumeration under the shell's existing filesystem authority. Only one `*` in the final path component is interpreted; the directory prefix is opened through the normal VFS permission path and matching names come only from `getdents`, so expansion cannot bypass traversal/open authorization. Matches are bounded by the existing 31-byte argument and eight-word command limits, and no-match/second-star/overflow conditions fail closed rather than passing attacker-controlled wildcard text through literally. Wildcard-bearing background and multi-stage pipeline stages are rejected before any child launch. There is no recursive glob, bracket/question syntax, sorting guarantee, command-name wildcarding or special hidden-file policy.

- G270 treats tilde expansion as fixed root-account pathname shorthand, not environment- or account-database authority. Only `~` and `~/...` map to the already-known `/home/root`; `~user` is rejected, the resulting argument remains capped at 31 bytes, and no lookup or privilege decision is derived from the expansion. Background and multi-stage pipeline forms are rejected before launch. The size-recovery changes used to keep the shell below 32 KiB remove only zero-initialization for scratch bytes that are overwritten before any read; C-string paths retain explicit terminators and the expanded command buffer is protected by a compile-time capacity inequality. There is no multi-user home lookup, parameter expansion, or composed tilde/wildcard/substitution evaluation.

- G271 treats startup files as bounded input to the existing shell authority, not as a privileged boot interpreter. The root shell opens `/etc/shrc` and `/home/root/.shrc` through ordinary VFS access, accepts at most 512 bytes from each, normalizes line endings only into the already-bounded semicolon grammar, and then uses the same parser/executor, expansion limits and process permissions as interactive commands. Missing, unreadable, oversized or syntactically invalid files are skipped rather than widening authority or blocking login. System configuration runs before per-root configuration. There is no recursive include/source facility, separate parser, signature bypass or hidden kernel configuration channel.
- G272 treats persistent shell history as untrusted user data, not executable startup configuration. The root shell writes raw nonblank interactive lines to `/persist/.sh_history` using ordinary VFS authorization and mode `0600` on creation; it never sources the history file automatically. The existing 32 KiB file-size ceiling bounds storage, and overflow truncates to the newest entry rather than allocating more state. Clean shutdown flushes only that file when possible and falls back to a global sync only when the new path has not yet become a committed journal record. Storage failures remain best-effort and cannot override read-only remount or damage containment. Because command text is stored verbatim, secrets typed into command arguments may persist; G272 provides no encryption, redaction, secure deletion or multi-user privacy boundary. Cross-boot QEMU uses the same NVMe image but fresh firmware variables so recovery evidence comes from the filesystem, not UEFI state.
- G273 gives standalone `ls` no authority beyond the invoking process. `/bin/ls.elf` opens the requested path with ordinary VFS credentials and consumes only `getdents` records already authorized by that descriptor; it does not parse raw filesystems, follow a separate mount namespace, bypass traversal checks or elevate UID/GID. Output is bounded by the existing finite directory namespace and streamed in eight-entry batches without retaining the full listing. Directory names are emitted as bytes returned by the ABI and directories receive a presentation-only `/` suffix. There is no recursive traversal, implicit wildcard evaluation, metadata probing, option parser or hidden-file exception that could widen reach beyond the explicit directory operand.
- G274 gives standalone `cat` only the read authority of its invoking process and one explicitly named path. The executable opens through ordinary VFS checks, streams through a fixed 512-byte buffer, and writes returned bytes to stdout without interpretation, decompression, executable loading or metadata mutation. It does not bypass file mode checks, expose raw block devices, recursively open references from file contents or retain a file-sized copy. Arbitrary file bytes may contain terminal control sequences because `cat` is intentionally a raw byte streamer; G274 does not sanitize presentation output or provide a trusted-text viewer.
- G275 gives standalone `echo` no authority beyond stdout and the argv bytes already supplied by its parent. It rejects startup vectors beyond the existing eight-entry ABI limit, scans no argument past the 31-byte ABI ceiling, retains no aggregate copy and performs no filesystem, environment or process lookup. There is deliberately no `-e`/escape parser, option language, wildcard expansion or command substitution inside the executable, so bytes cannot acquire new interpretation after spawn. Argument bytes may still contain terminal control sequences when supplied programmatically; `echo` is presentation output rather than a trusted terminal-sanitization boundary.
- G276 gives standalone `pwd` only cwd-observation authority plus stdout/stderr output. It accepts no operands, allocates one fixed 256-byte buffer and asks the kernel for the process's already-authorized current-directory path through `getcwd`; it performs no lookup of caller-supplied paths, mutation, directory enumeration, environment expansion or independent symlink traversal. The returned path may reveal namespace names already implicit in the process cwd, so G276 is an observation interface rather than a secrecy boundary.
- G277 gives standalone `mkdir` only one bounded namespace-create operation for the single caller-supplied path. The kernel remains authoritative for path length/component bounds, parent traversal, parent write+execute permission, credentials, process umask, read-only mounts, namespace serialization and allocation limits. The executable does not synthesize missing parents, retry across alternate paths, change ownership/mode after creation or recursively mutate the tree. A successful call can intentionally create one visible directory, so invocation itself is the mutation authority boundary.
- G278 gives standalone `rm` and `rmdir` one bounded namespace-removal operation each for one caller-supplied path. The executables do not recurse, enumerate descendants, broaden wildcards, retry alternate names, follow a force policy or cross file/directory removal semantics. The kernel remains authoritative for parent traversal, sticky-directory ownership, credentials, read-only mounts, busy references, non-empty-directory checks, deferred open-file lifetime and namespace serialization. Successful invocation intentionally removes one namespace entry, so caller authority to name that path is the mutation boundary; retained open descriptions continue to obey the existing unlink-lifetime contract.
- G279 gives standalone `mv` one bounded rename authority over two caller-supplied paths and gives standalone `cp` read authority over one source plus create/truncate/write authority over one destination. Neither executable recurses, expands wildcards, interprets file contents or synthesizes additional target paths. The kernel remains authoritative for traversal, credentials, sticky-directory policy, mount boundaries, read-only state, busy references and namespace serialization. `cp` compares an existing destination mount/node/generation identity with the opened source before truncation, so an exact-path or hard-link alias cannot destroy the source through self-copy. Copy output is still non-transactional: an I/O or no-space failure after destination truncation may leave a partial destination; G279 does not claim atomic replacement or rollback.
- G280 gives standalone `stat` observation authority over exactly one caller-supplied pathname plus stdout/stderr output. The kernel performs all traversal and permission decisions through the existing `stat`, `statowner` and `stattimes` calls; the executable does not open file contents, enumerate directories, mutate metadata, follow a second path, expand wildcards or allocate based on metadata values. It can intentionally reveal inode identity, ownership, modes, size and timestamp ticks already exposed by those ABIs, so it is a metadata observation interface rather than a secrecy boundary.
- G281 gives standalone `head`, `tail`, `wc` and `grep` read-only authority over one caller-supplied regular-file path plus stdout/stderr. All four inherit existing traversal/open permissions and retain fixed stack state rather than file-sized buffers. `head` and `wc` require only sequential reads; `tail` and matching `grep` additionally require the descriptor to be seekable. `grep` accepts one literal pattern capped at 31 bytes and does not interpret regex metacharacters, recurse, expand paths or open additional files. The utilities can reveal file contents and derived counts to an already-authorized caller, so they are observation tools rather than confidentiality boundaries.
- G282 gives standalone `hexdump` read-only observation authority over one caller-supplied file path plus stdout/stderr. Existing traversal/open permissions remain authoritative; the tool allocates only a 16-byte row and a four-byte formatting buffer, never mutates or maps the file, and stops after 256 input bytes even when the file is larger. It can reveal those authorized bytes in hex/ASCII form, so it is an inspection tool rather than a confidentiality boundary.
- G283 gives standalone `ps` observation authority only through the already-published read-only `/proc/processes` pseudo-file. The executable opens no caller-selected paths, performs no process-control syscall, and retains only one fixed streaming buffer. It can reveal the process metadata procfs already exposes—PID, PPID, state, ticks, descriptor/socket counts and bounded name—so it is an observation interface rather than a process-isolation or confidentiality boundary.
- G284 adds public signal-delivery authority through ABI 1.25 syscall 128 `kill`, but the syscall performs no independent authorization: it resolves the PID and delegates to the existing process-table `sendSignal` path, which retains root/same-UID checks, supported-signal validation and terminal-target rules. The standalone `kill` frontend further refuses PID 1 and the active shell PID 2, defaults to SIGKILL and accepts only numeric signals 1-63; these frontend restrictions are defense-in-depth, not the kernel security boundary. Terminal foreign targets are finalized after signaling and self-termination leaves the active address space before reclamation. Standalone `sleep` adds no authority beyond delaying its own process for 1-100000 scheduler ticks. Neither utility performs pathname, filesystem or network access.
- G285 gives standalone `mount` observation authority only through the already-published read-only `/proc/mounts` pseudo-file. The executable accepts no caller-selected path, opens no writable descriptor, and retains only one fixed 512-byte streaming buffer. It can reveal mount source, target, filesystem kind and read-only/read-write state that procfs already exposes, but it cannot mount, unmount, remount, alter flags, probe arbitrary paths, or bypass existing procfs access semantics; it is an inspection interface rather than a mount-control or confidentiality boundary.
- G286 gives standalone `df` only the existing `statfs` observation authority for a caller-selected bounded path (default `/`). It can reveal filesystem capacity, free/available block and inode counts, mount ID, filesystem type and read-only/shared/synthetic flags already exposed by ABI 1.14, but it opens no descriptor and performs no namespace or storage mutation. It is not a quota, reservation, mount-management or free-space confidentiality boundary; shared-pool flags explicitly warn callers not to sum capacities across mounts.
- G287 exposes one coarse filesystem-integrity observation through ABI 1.26 syscall 129 `fscheck`. The syscall rejects all arguments, switches to the kernel address space only for the established callback, and returns 0 only when persistent storage is mounted, the bounded VFS validator passes and the active persistence generation passes `Store.check()`. Structural validation failure returns 1, while device/read failures remain negative operational errors such as `EIO`, so an I/O outage is not mislabeled as corruption. Any caller may learn clean versus corrupt versus unavailable/operational failure, but receives no inode, block, journal payload or corruption-location detail. The interface cannot repair, write blocks, remount filesystems or invoke arbitrary persistence methods; `/bin/fsck.elf` adds only fixed status text around that check.
- G288 gives standalone `uname` observation authority only through the already-published read-only `/proc/version` pseudo-file. The executable accepts no operands, opens no caller-selected path, retains one fixed 128-byte buffer and performs no platform-control syscall. It can reveal the kernel version/architecture/runtime string that procfs already exposes, but cannot change hostname/domain identity, enumerate hardware, inspect arbitrary kernel memory or bypass procfs access semantics.
- G289 gives standalone `env` observation authority only over the calling process environment already copied onto its startup stack. The executable accepts no operands, traverses at most eight pointers, bounds each entry to the generated 63-byte payload limit, requires a nonempty `NAME=VALUE` form and emits entries without filesystem access or mutation. Environment contents are therefore not a confidentiality boundary inside the same process; the utility cannot inspect another process, alter the parent shell, synthesize variables, execute a command, or bypass the kernel spawn-vector limits.
- G290 gives standalone `edit` caller-authorized read/write authority over exactly one supplied pathname. Existing traversal/open/create/write permissions, read-only mounts, file-size limits and descriptor error propagation remain authoritative; the program adds no privilege, raw block, mount, process or network interface. It retains at most 4 KiB of file content and bounded command/read-ahead buffers, rejects command overflow before interpretation and does not interpret file bytes as commands. `w`/`wq` open the selected target with create/truncate, write the bounded in-memory document and request `fsync` (falling back to global `sync` only when unsupported), so save is intentionally **not** an atomic replacement guarantee: a write, durability or crash failure after truncation may leave a truncated or partial target. `q` can deliberately discard unsaved in-memory edits.
- G291 does not widen `cp` authority: the caller still selects exactly one readable source and one creatable/writable destination under the existing VFS permission, mount and inode-identity checks. The new shared copy core only changes progress handling inside that authority. Every nonempty read chunk must be fully written before another read occurs, short writes are retried at the remaining suffix, and a zero-progress write fails as `EIO` instead of creating an unbounded loop. This is robustness, not transactionality: because G279/G291 still open the destination with truncate before streaming, later I/O or capacity failure may leave a partial destination and there is no rollback, atomic replacement, reflink or metadata-complete copy guarantee.
- G292's `zigos_abi.h` grants no runtime authority. It is generated compile-time description data: public constants, fixed layouts and the process startup signature. It deliberately declares no syscall-wrapper functions and cannot perform I/O, allocate memory, map pages, mutate process state or cross the kernel boundary by itself. The independently linked conformance ELF uses the existing common startup object only to prove the header is consumable by freestanding C and that startup auxv values match the description; any actual syscall authority still requires explicit wrapper/raw-syscall code and remains subject to the kernel's ordinary pointer, credential and capability checks.
- G300 gives a process outbound IPv4 TCP **active-open** capability only when a retained e1000e device is present and ABI capability bit 11 is advertised. A caller can select a nonzero IPv4/port, causing a SYN to leave the guest and exposing the guest's chosen ephemeral port; only a SYN-ACK/RST matching the stored peer MAC/IP/port tuple may complete/refuse the connection, and local/peer addresses plus connect readiness are observable through the existing descriptor APIs. TCP uses a distinct generation-checked descriptor resource and shares the existing per-process socket quota with UDP. The milestone does **not** expose listen/accept, TCP application `send`/`recv`, arbitrary receive buffers, passive-open state or graceful FIN close; those calls remain unsupported rather than silently using UDP semantics. The live proof's host listener is loopback-only, so CI does not publish a LAN service. The current ISN is deterministically derived from boot-local tick/slot/generation and must not be treated as cryptographically unpredictable; G300 therefore does not claim resistance to off-path TCP sequence prediction, hostile Internet deployment, TLS/confidentiality, congestion control or a production TCP security boundary.
- G301 adds bounded inbound IPv4 TCP **listen/passive-open** authority. A process may reserve one local TCP port and request backlog 1-4; the kernel may answer matching inbound SYNs with SYN-ACK and retain the peer MAC/IP/port plus a fixed control block until the handshake establishes, resets or times out. The listener becomes poll-readable when an established pending handshake exists, but G301 deliberately exposes no `accept` operation and `getpeername` on the listener remains `ENOTCONN`, so no pending peer becomes an application descriptor yet. Backlog storage is fixed and excess SYNs are dropped rather than allocating memory. The QEMU proof exposes only a host-loopback `hostfwd` endpoint and does not publish a LAN listener. Passive ISNs are deterministic boot-local values, not cryptographic randomness; G301 therefore does not claim SYN-flood resilience, SYN cookies, Internet-grade sequence unpredictability, application-data confidentiality, congestion control or production server hardening.
- G302 promotes one established passive handshake into an application-visible TCP descriptor through `accept`. This grants the accepting process stable peer/local endpoint metadata and ownership of the established control block, but still no TCP payload `send`/`recv` authority. Acceptance is bounded by the fixed listener backlog, the existing per-process socket quota, the global socket-slot bound and descriptor limits. Optional peer-address memory is validated before queue mutation; allocation failure leaves the handshake queued, and peer-copy failure closes the provisional descriptor before the pending entry can be consumed. A nonblocking listener returns `EWOULDBLOCK`; a blocking listener sleeps only on its generation-tagged socket-read wait key. The listener remains unconnected and excess/new handshakes remain subject to G301 fixed backlog behavior. G302 does not add SYN cookies, arbitrary receive buffering, TLS/confidentiality, congestion control, Internet-grade ISN randomness or production server hardening.
- G303 changes UDP `send`/`sendto` authority from whole-request rejection above the ABI scratch limit to a bounded positive short return. At most 1,024 caller bytes are validated, copied and transmitted per syscall; a larger request leaves the suffix untouched and reports exactly how many bytes were emitted. This intentionally means one oversized UDP request may produce a shorter datagram and is not a POSIX datagram-atomicity guarantee. The live proof sends only to host loopback port 39003 through QEMU slirp, and host-side byte comparison verifies both deterministic prefixes. G303 adds no transmit queue, fragmentation, writer blocking/wakeup, TCP payload authority, retransmission, congestion control, confidentiality or hostile-network hardening; TCP `send` remains unsupported until G313.
- G305 adds bounded TCP half-close authority through a new socket-specific syscall rather than overloading the privileged OS-shutdown call. `SHUT_RD` changes only the caller-owned socket slot and grants no new ingress authority. `SHUT_WR` may emit one FIN to the already-authorized connected peer; the control block is restored if that transmission fails, and repeats emit no additional FIN. After success the descriptor remains generation-checked and peer-addressable but is no longer poll-writable. UDP/listener/unconnected descriptors cannot use this authority. The live proof is confined to QEMU slirp and a host-loopback TCP listener. G305 does not implement FIN retransmission, FIN-ACK/TIME-WAIT progression, TCP payload I/O, congestion control, TLS/confidentiality, Internet-grade sequence hardening or graceful descriptor close; those remain later milestones.
- G307 adds only bounded socket-policy observation and one existing scheduling-mode mutation. `TYPE`, `PROTOCOL` and `ACCEPTCONN` reveal facts already implied by the caller-owned descriptor and grant no packet, peer or namespace authority. `NONBLOCKING` changes only whether operations on that socket may sleep; it shares the pre-existing syscall-107 slot bit and does not bypass pointer, descriptor, peer, protocol or readiness checks. Unsupported levels/options and writes to read-only facts fail explicitly with errno -92. G307 does not expose buffer sizes, keepalive, raw protocol options, TCP payload controls, congestion/retransmission tuning, credentials or host-network configuration; the live proof remains confined to QEMU slirp and host-loopback fixtures.

- ABI 1.24 makes foreground pipeline launch atomic with respect to terminal ownership. The `foreground_process_group` spawn flag is valid only with `new_process_group`; the kernel first completes child image installation and descriptor remapping, then performs the controller-authorized foreground-PGID handoff through fd 0 before returning from `spawnv`. It grants no arbitrary PGID selection, does not apply to background launches and preserves direct-child/session/controller authorization. Foreground changes wake blocked terminal readers only so they revalidate ownership, allowing partial-pipeline rollback to restore shell ownership before reap without leaving a stale terminal sleeper.

### Filesystem and persistence

- Paths are bounded and normalized; traversal, rename cycles and cross-mount rename are rejected.
- User pathname payloads are capped at 255 bytes and individual slash-delimited components at 31 bytes. The complete path is validated before lookup or namespace mutation, including both sides of rename/link and both symlink target/destination strings, so an earlier missing component cannot suppress a later bounds failure. Exactly 255 bytes remains valid; 256+ bytes or a 32-byte component returns `ENAMETOOLONG`. C-string syscall copying distinguishes inaccessible user memory (`EFAULT`) from missing termination/overlength (`ENAMETOOLONG`). These fixed limits are a bounded ZigOs VFS policy, not a claim of dynamic POSIX `PATH_MAX`/`NAME_MAX` support.
- G248 adds deterministic model-based adversarial coverage for the bounded resolver, rename/replacement and unlink state machines. Eight fixed seeds produce 4,096 transitions over reusable namespace slots and accepted alternative path spellings; every seed self-checks coverage of all operation classes/path variants and successful rename/replacement/unlink; after every operation, structural invariants, reference-model visibility/identity/generation/canonical paths, namespace accounting and drained lock/reference state are checked. Failure paths for absent sources/parents, overlong components and file/directory type mismatches are required to be failure-atomic. This improves regression detection but is not a proof of memory safety or exhaustive state coverage: the seed set is finite, the model is single-threaded and intentionally bounded, the model itself remains single-threaded even though G249 separately stress-tests a bounded concurrent mutation subset, and broader filesystem/directory fuzzing remains G414.
- G249 introduces a coarse ticket lock only for the concurrent create/path-write/rename/unlink target set. Those four operations serialize before pathname resolution and retain the lock through namespace/data mutation, preventing one target operation from invalidating another target operation's resolved node while shared bounded dentry/node/data allocators are changing. The tested lock order is namespace operation before inode/page/cache/data-pool locks and the structural validator requires the ticket queue to drain. Four barrier-synchronized host threads perform 1,024 built-in target operations with exact mutation/ticket conservation, and the complete QEMU/fault/persistence matrix remains green. This reduces a concrete race surface but must not be interpreted as global VFS thread safety: plain readers and other namespace mutations such as mkdir, link, symlink, mount/unmount, descriptor tables, pseudo registries and restore/administrative paths are not all covered by this lock, and no linearizability claim is made for those interactions.
- G250 exercises the persistent A/B journal against physical-block corruption rather than only simulated write failure. After a healthy A=3/B=4 image is produced, independent copies corrupt exactly one newest-slot header block byte or one newest-slot payload block byte. The older slot must remain independently valid, QEMU must reject the damaged newest candidate by header CRC or payload CRC, restore generation 3, increment recovery accounting, and never expose generation-4-only data. Recovery itself must not rewrite either damaged image. Header corruption is intentionally observable as `corrupt_headers=1`, so that diagnostic boot is classified as recovered-but-not-clean; payload CRC rejection leaves header-error accounting at zero. The test does not prove arbitrary multi-block corruption tolerance, repair, Byzantine media behavior, or survival when both A/B generations are invalid. G251 separately defines the on-disk compatibility and supported recovery guarantees.
- G251 treats on-disk compatibility itself as a security/reliability boundary. `docs/PERSISTENCE-COMPATIBILITY.md` is authoritative for v1/v2/v3 decoding, one-way migration to v3, little-endian geometry/layout, CRC coverage, commit ordering and fallback limitations. Unknown future versions are deliberately not accepted as forward-compatible, and booting an older kernel on newer-format media is explicitly unsafe unless a later contract says otherwise: a recognized older slot may be selected while an unknown newer slot is rejected. The document also prevents overclaiming CRC recovery by stating that read I/O errors fail as I/O, both-slot loss is fatal, and CRC-valid semantic restore failure does not retry the older generation. Any format change must update source, migration/recovery tests, this contract and the permanent verifier together.
- The retained EFI partition is mounted read-only through a bounded FAT16 parser: only 8.3 entries are staged, file/directory/depth counts are fixed, LBAs and volume extents are checked, directory and file chains are traversed through EOC, same-chain revisits are rejected as loops, one global bitmap rejects cross-linked ownership, and invalid current/next clusters are classified as out-of-range. VFS publication occurs only after the complete integrity scan. Classified FAT-structure failures erase staging, retain one quarantine reason/event and mount an embedded read-only `/boot`; mount-time device/I/O failures remain fatal. Runtime backed-file read failures propagate as VFS `InputOutput` and userspace `EIO`, preserve the buffer and descriptor offset, and may be retried. CPL3 descriptor reads switch to the kernel CR3 for MMIO-backed I/O and restore the process CR3 before userspace copying. Phase-valid NVMe error completions are consumed and acknowledged so they cannot wedge the completion queue. Shared sector buffers are ticket-locked, and backed-file logical sizes are excluded from RAM-resident accounting. Quarantine does not repair the disk and does not claim transactional rollback for a later unrelated VFS resource failure during publication.
- `/persist` uses alternating generations, payload CRCs, payload-before-header ordering, flushes and an FUA commit header.
- Global sync and stable-path file fsync build in a separate scratch payload; the committed in-memory baseline changes only after payload and FUA header success.
- Global sync prevalidates every active writable mount before I/O, treats RAM filesystems as immediately synchronized, skips read-only mounts, commits the configured persistent backend once and rejects unsupported or duplicate writable durable backends without advancing the journal.
- ABI 1.13 exposes only a root-gated empty-target `tmpfs` mount subset. It rejects unknown flags, non-null mount data and unsupported filesystem names; unmount requires the exact mounted root and fails while child mounts, retained descriptors, referenced paths or any occupied process working directory remain inside. This is namespace-lifetime protection, not a complete privilege boundary because the current credential/capability model remains incomplete.
- ABI 1.14 `statfs` exposes bounded allocator/backend accounting only. Shared-block/shared-node flags explicitly prevent RAM root, tmpfs and zigos_persist from being interpreted as isolated capacity pools; pseudo filesystems report synthetic zero-block capacity; real FAT free clusters come from a complete FAT-entry scan; embedded fallback boot files report shared RAM capacity. `available_blocks` currently equals `free_blocks` because there is no quota/reservation policy. statfs capacity is accounting information, not a storage-isolation boundary or authorization primitive.
- ABI 1.15 `stattimes` exposes four stored inode ticks for creation, modification, metadata change and access. G238 defines them as samples of the boot-local 100 Hz persistent-runtime counter: nominal precision is 10 ms, operations within one tick may tie, the counter resets to zero at every boot, and a later post-reboot update can therefore be numerically smaller than an older persisted value. Successful data, metadata, namespace and access operations update only their documented fields; failed operations, stat/stattimes, synchronization, zero-byte non-truncating I/O, EOF getdents, read-only mapped-file access and kernel-internal scans are timestamp-neutral. `/persist` journal v3 carries all four values plus inode ownership in each record, accepts v1 payloads by synthesizing restore-time timestamps and v1/v2 payloads as root-owned `0:0`, and reapplies saved metadata after namespace/hard-link reconstruction; full `fsync` persists current metadata while `fdatasync` keeps committed creation/change/access metadata and advances the data modification tick. Timestamp values are therefore not an authorization primitive, audit log, real-world clock or cross-reboot ordering source.
- ABI 1.16 `statowner` exposes a fixed 8-byte pair of 32-bit owner UID/GID fields. VFS inodes store this metadata; files created through descriptor `O_CREAT`, directories and symbolic links inherit the creating process credentials, and hard links keep one shared inode owner. `/persist` journal v3 stores UID/GID and treats legacy v1/v2 records as root-owned `0:0`; full `fsync` records current owner metadata while `fdatasync` retains committed ownership. G240 makes this metadata authoritative for the bounded VFS: non-root callers select exactly one owner, matching-primary-group or other mode class; directory traversal requires execute, namespace mutation requires parent write+execute, requested open access is checked once, process launch requires execute, and chmod requires inode ownership. UID 0 is the explicit administrative bypass. Already-open descriptions retain their granted access after chmod. ABI 1.17 adds syscall 124 `umask`: each process carries a bounded nine-bit creation mask, children inherit it, updates return the previous mask and reject bits outside `0777` without changing state, and file/directory creation applies the mask once to rwx permissions. chmod and existing objects are not masked; hard links preserve the target mode and symlinks retain their fixed mode. Userspace child spawn preserves parent UID/GID. G242 preserves setuid/setgid metadata without granting credentials: executable loading checks execute permission and child creation inherits caller UID/GID without consuming inode owner/mode metadata. G243 expands stored mode metadata to validated `07777` and enforces sticky-directory removal. Parent write+execute remains necessary; if the parent has sticky `01000`, removing an entry by unlink, empty-directory rmdir, rename source movement or rename destination replacement additionally requires UID 0, ownership of the directory or ownership of the victim inode. Source and replacement victims are checked independently, and exact rename-to-self remains a no-op. ABI 1.18 `flock` is coordination rather than authorization: regular-file shared/exclusive locks are owned by open descriptions, separately opened aliases contend by inode generation, blocking callers sleep/wake through the process table, and ordinary read/write/mmap paths deliberately do not enforce lock ownership. ABI 1.19 `lockrange` applies the same advisory boundary to bounded byte ranges: at most eight normalized half-open segments live on one open description, independently opened aliases conflict by inode generation, nonblocking conflicts preserve owner state, partial unlock/replacement can split and merge ranges, and blocking conversion releases only the requested overlapping owner range before sleeping. Whole-file and byte-range lock families are separate advisory namespaces. Final close, process teardown and reboot discard both; neither grants access or persists to the journal. ABI 1.20 `watchdir` is also coordination/observation rather than authorization: callers must already hold an open directory descriptor, watches begin at the current mutation sequence and expose only later successful namespace changes for that directory. The shared VFS journal is bounded to 64 records and reports an explicit overflow event instead of silently claiming complete history; separate watches have independent cursors while dup/fork aliases share one cursor. Caught-up reads return `EWOULDBLOCK`, poll exposes readable/error/hangup state, and stale watched generations cannot be reused. Watch state and event history are transient and never enter the persistent journal, so this interface is not a durable audit trail, rollback log or access-control mechanism. Supplementary groups, `chown`, set-ID execution and setgid-directory GID inheritance remain open.
- The file-data page cache is bounded to sixteen pages and keys entries by inode generation and logical page so reclaimed node slots cannot reuse stale data; the authoritative block pool remains write-through.
- Cache page bytes are allocated independently from the post-bootstrap physical-memory manager; entries carry page addresses, invalidation and eviction return those pages, and shutdown requires cache allocations and releases to balance before final PMM accounting.
- Runtime service checks a bounded low-watermark policy and evicts only clean LRU entries. Dirty resident pages are never pressure victims, and their independent dirty ledger remains authoritative until successful synchronization.
- Each inode owns eight logical-page writer ticket locks. Data mutations acquire affected page locks in ascending order beneath the inode data lock and release them in reverse; shutdown requires exercised page locks and zero outstanding tickets.
- Same-page writes are therefore explicitly serialized, including cached-page mutation, truncate, preallocation, hole punching and sparse restore. The outer inode lock still serializes different-page writes, so parallel page writes are not claimed.
- An independent one-byte dirty-page bitmap per inode survives cache eviction, while resident entries must mirror the corresponding generation-keyed dirty bit.
- Successful global sync clears dirty state only after a validated all-writable-mount plan and journal success; RAM-backed regular-file fsync/fdatasync clears only its target immediately, persistent file sync clears only after journal success, and rejected plans preserve dirty bits for retry. A real persistent journal write or flush error is different: it records the failed stage, remounts the exact `/persist` mount read-only once, discards that mount's unsynced dirty ledger, preserves readable live bytes and the running Store's prior committed baseline, and makes later mutations and synchronization return `EROFS`. Because header flush follows an FUA header write, a header-flush error leaves on-disk generation durability indeterminate; reboot selects the newest valid generation.
- Journal restoration and read-only mount adoption establish clean baselines, inode destruction discards obsolete dirty bits, and every release profile requires zero dirty cache entries, pages and nodes at shutdown.
- Asynchronous writeback permits only one active generation-tagged request; scheduling does not clear dirty state, and one later runtime service pass consumes at most one request.
- RAM-backed requests complete by clearing only the validated target; stable persistent requests use data-only A/B journal commit ordering. Busy, unsupported and stale outcomes retain dirty pages for retry or global sync; a durable I/O failure enters the same fail-stop read-only containment state instead.
- Request/completion/pass and queued/completed-page counters are conserved at shutdown; dedicated QEMU requires a nonzero six-page asynchronous proof, while other profiles may remain validly idle.
- Ordinary reads hold the inode data lock; every data/size/allocation mutation invalidates that inode's cached pages, and shutdown requires the cache lock to have no outstanding ticket.
- Large cache-array scans use indexed/reference traversal; the source contract rejects by-value iteration that previously created a kernel-stack-sized temporary during QEMU execution.
- Persistent file fsync and fdatasync copy unrelated records from the last committed generation, excluding unrelated dirty VFS state. Full fsync records current mode; fdatasync retains committed mode while advancing data, size and sparse allocation. A forced-termination four-boot test verifies both policies; nonpersistent regular files use immediate target-only synchronization.
- Mount selects the newest completely valid generation and can fall back from a corrupt newest slot.

### Devices and networking

- `/dev/null`, `/dev/zero` and `/dev/console` are published through a fixed-capacity kernel-only live registry and retain independent per-node operation tables. Matching registries publish bounded live `/proc` kernel summaries and `/net` network summaries; withdrawal rejects referenced nodes, ordinary namespace mutation remains read-only, and kernel-owned pseudo mounts cannot be detached through the userspace tmpfs-only unmount ABI.
- Network receive queues and active driver UDP endpoints are bounded; ABI discovery reports four usable hardware endpoints rather than eight bookkeeping slots.
- Retained NVMe and e1000e operation is bounded and polling-based during the permanent runtime.

## Known security gaps

The following are not mitigated and must be treated as open security work:

- owner/group/other mode checks, process umask and sticky-directory removal are enforced against UID plus one primary GID; advisory whole-file `flock` coordinates cooperating processes but is not an authorization boundary; setuid/setgid metadata is stored but deliberately inert at execution, while supplementary groups, credential-changing syscalls, `chown`, set-ID execution and setgid-directory inheritance remain unimplemented;
- no capability enforcement policy across all syscalls;
- no complete userspace signal-frame, handler or permission model;
- no SMEP or SMAP enablement and audit;
- no complete kernel W^X audit, KASLR/ASLR or relocation hardening;
- no stack canaries or independently guarded kernel stacks for every execution context;
- no IOMMU setup, DMA remapping or per-device DMA isolation;
- no system-wide cross-resource pressure policy or OOM victim selection;
- no cryptographic executable, package or persistent-data trust policy;
- no comprehensive fuzzing corpus for every pointer-bearing syscall and parser;
- no SMP-safe scheduler, allocator, VFS or device registry; the live pseudo registries are bounded kernel-only publication tables, not a hotplug-safe general registry;
- no side-channel, speculative-execution or physical-attack defence claim.

## Security acceptance conditions

ZigOs must not claim hostile-workload security until, at minimum:

1. credential lifecycle, supplementary groups, ownership-changing operations and special-mode authorization are completed and stress-tested;
2. every syscall has a documented capability and permission rule;
3. SMEP/SMAP, kernel W^X, stack hardening and ASLR are enabled and tested;
4. DMA is constrained with an IOMMU or an explicit trusted-device/bounce-buffer policy;
5. all pointer-bearing ABI paths are fuzzed with reproducible corpora;
6. signals have complete permission, frame and return semantics;
7. resource pressure has a documented recovery/OOM policy;
8. SMP mutation is synchronized and stress-tested;
9. executable installation has an explicit trust/signing policy;
10. physical Intel and AMD systems pass repeated malformed-input and recovery sessions.

Until those conditions are met, the correct statement remains: ZigOs is an experimental, bounded research OS and is not secure against hostile workloads.
